# PPT 디자인 가이드 - 경제형

원본 PPT의 블러 이미지는 디자인 스타일이 아니라 익명화/권리 보호를 위한 후처리로 본다. 실제 제작본에서는 내용과 직접 관련된 선명한 이미지와 아이콘을 사용하고, 외부 공유나 익명화가 필요한 경우에만 블러/마스킹/모자이크를 적용한다.

## 1. 디자인 원칙

- 장표는 `스토리 전달`과 `검토 자료`를 분리해 설계한다.
- 이미지는 장식이 아니라 내용 이해를 돕는 근거로 사용한다.
- 아이콘은 문장 요약, 단계 구분, 기능/상태 표시처럼 의미가 있을 때만 사용한다.
- 오렌지는 강조, 결론, 진행 신호에만 제한적으로 사용한다.
- 블루는 표, 일정, 운영 문서, 검토 자료의 구조색으로 사용한다.
- 블러는 스타일이 아니라 비식별 처리다. 최종 공개본이 아니라면 원본 맥락을 알아볼 수 있게 선명도를 유지한다.

## 2. 컬러 가이드

| 역할 | 색상 | HEX | 사용처 |
|---|---:|---|---|
| 기본 배경 | Black | `#050505` | 발표/피칭형 장표, 강한 몰입감 |
| 보조 배경 | Charcoal | `#171717` | 어두운 장표의 박스/구획 |
| 핵심 강조 | Orange | `#F37321` | 핵심 키워드, 라벨, 결론, 진행 표시 |
| 신호 강조 | Signal Orange | `#FF7900` | 번호, 섹션 전환, CTA성 강조 |
| 강한 결론 | Deep Orange | `#EA5628` | 결론 바, 리스크/이슈 강조 |
| 문서 구조 | Blue | `#1E4A8C` | 표 헤더, 일정표, 검토 자료 |
| 보조 구조 | Teal Blue | `#156082` | 보조 구분, 하위 카테고리 |
| 기본 바탕 | White | `#FFFFFF` | 검토형/문서형 장표 |
| 보조 바탕 | Soft White | `#F4F6F9` | 카드, 표 배경, 캡션 영역 |
| 구분선 | Light Gray | `#E8E8E8` | 라인, 분리선, 비활성 요소 |

권장 비율은 배경색 70~85%, 보조 회색 10~20%, 오렌지/블루 강조 5~10%다.

## 3. 타이포그래피

- 기본 폰트는 `Pretendard` 계열을 사용한다.
- 분위기형 제목이나 큰 숫자는 `Pretendard Thin`, `Light`, `Medium`을 사용한다.
- 핵심 키워드, 결론, 라벨은 `Pretendard ExtraBold` 또는 `Black`을 사용한다.
- 제목은 28~36pt, 중간 헤더는 18~24pt, 본문은 10~16pt, 메타 정보는 8~10pt를 기준으로 한다.
- 작은 본문은 발표용이 아니라 검토용 장표에서만 허용한다.
- 원본의 난수 텍스트, 깨진 문장, 부자연스러운 줄바꿈은 익명화로 인한 노이즈다. 실제 제작본에서는 의미 있는 문장과 자연스러운 문단 구조로 정리한다.

## 4. 문장과 줄바꿈 정책

텍스트는 깔끔하고 가독성 있게 보여야 하며, 어절이 끊기지 않아야 한다.

- 한 줄은 가능하면 18~28자 안팎으로 유지한다.
- 줄바꿈은 조사/어미 뒤가 아니라 의미 단위로 끊는다.
- 한글 어절 중간에서 줄이 바뀌지 않게 텍스트 박스 폭을 먼저 조정한다.
- 긴 제목은 글자를 줄이기보다 문장을 압축하거나 2줄 제목으로 재작성한다.
- 본문은 2~4줄 단락으로 나누고, 한 단락 안에서 핵심어를 1개만 강조한다.
- 캡션은 1~2줄만 사용하고, 이미지 해석에 필요한 정보만 남긴다.
- 표 안의 문장은 명사형으로 줄이고, 문장형 설명은 표 밖 주석으로 뺀다.
- 임시 텍스트가 필요하면 난수나 무의미한 문자가 아니라 실제 길이에 가까운 예시 문장을 사용한다.

권장 줄바꿈 예시:

| 좋음 | 피해야 함 |
|---|---|
| 핵심 장면을 먼저 보여주고<br>근거는 하단에서 보완 | 핵심 장면을 먼저 보여주<br>고 근거는 하단에서 보완 |
| 사용자 반응을 기준으로<br>우선순위를 재정렬 | 사용자 반응을 기준으<br>로 우선순위를 재정렬 |
| 내부 검토용 자료는<br>원본 이미지를 유지 | 내부 검토용 자료<br>는 원본 이미지를 유지 |

## 5. 이미지 사용 정책

이미지는 장표 내용과 직접 연결되어야 한다.

### 사용해야 하는 이미지

- 인물/상황/공간을 설명하는 장표: 실제 장면, 현장 사진, 인물 맥락 이미지
- 서비스/제품/기능을 설명하는 장표: 실제 UI, 제품 이미지, 스크린샷
- 리서치/사례 장표: 원문 캡처, 기사/자료 화면, 사례 이미지
- 일정/운영 장표: 프로세스 캡처, 산출물 예시, 워크플로 이미지
- 콘셉트 장표: 주제와 연결되는 상징 이미지나 생성 이미지

### 피해야 하는 이미지

- 내용과 관계없는 분위기용 배경 이미지
- 의미 없는 추상 배경, 과도한 그라데이션, 장식용 스톡 이미지
- 실제 제품/로고/화면을 대체하는 가짜 이미지
- 텍스트를 읽어야 하는데 과도하게 블러된 캡처

### 블러/마스킹 기준

- 블러는 개인정보, 미공개 정보, 저작권 이슈, 고객명, 얼굴, 계정 정보, 수치 등을 가릴 때만 사용한다.
- 블러 처리 후에도 이미지의 종류와 역할은 알아볼 수 있어야 한다.
- 핵심 근거가 되는 텍스트나 수치는 블러하지 말고, 필요한 경우 별도 요약 텍스트로 재작성한다.
- 내부 검토용은 가능한 선명한 원본 이미지를 사용하고, 외부 공유본에서만 비식별 처리한다.

## 6. 아이콘 사용 정책

아이콘은 "무엇을 말하는지 빠르게 분류하는 장치"로 사용한다.

- 단계: 번호 아이콘, 화살표, 체크, 플래그
- 상태: 확인, 보류, 위험, 완료, 진행 중
- 기능: 검색, 문서, 캘린더, 사람, 메시지, 설정, 데이터
- 비교: plus, minus, versus, split, merge
- 주의/결론: alert, target, pin, marker

스타일 규칙:

- 선형 아이콘을 기본으로 하고, 획 두께는 1.5~2pt 수준으로 맞춘다.
- 아이콘 색은 기본 흰색/검정/회색, 강조 시 오렌지 또는 블루만 사용한다.
- 한 장표에서 아이콘 스타일을 섞지 않는다.
- 아이콘은 텍스트 박스의 장식이 아니라 라벨 앞, 단계 앞, 표 헤더, 콜아웃 포인트에 배치한다.
- 아이콘만으로 의미가 불분명하면 짧은 라벨을 함께 붙인다.

## 7. 여백과 장식 이미지 배치

원본의 느낌은 화면을 꽉 채우는 장식보다 `큰 여백 + 작은 정보 단서 + 내용 관련 이미지`의 균형에서 나온다.

### 공통 여백

- 상단에는 작은 섹션 탭과 메타 정보만 두고, 본문과 분리한다.
- 좌우 기본 여백은 넉넉하게 유지한다. 본문형 장표는 좌우 5~7%, 시네마틱 장표는 6~10%를 기준으로 한다.
- 제목과 본문 사이에는 충분한 숨 쉴 공간을 둔다. 제목 바로 아래를 표나 이미지로 붙이지 않는다.
- 하단 여백은 캡션, 결론 바, 페이지 정보가 들어갈 공간으로 남겨 둔다.
- 빈 공간은 실패가 아니라 시선 유도 장치로 본다. 특히 블랙 장표에서는 어두운 빈 공간을 적극적으로 남긴다.

### 시네마틱 장표의 이미지 배치

- 배경 이미지는 풀블리드로 깔 수 있지만, 텍스트 영역에는 어두운 오버레이를 적용한다.
- 핵심 이미지는 중앙 정렬보다 약간 우측 또는 하단으로 치우치게 배치해 영화적 장면감을 만든다.
- 인물/제품/공간 이미지는 화면 한쪽에 무게를 주고, 반대쪽은 제목과 여백으로 비운다.
- 작은 보조 이미지는 우하단, 우측 중단, 또는 하단 띠 영역에 배치한다.
- 이미지 위 텍스트는 짧게 둔다. 긴 설명은 별도 검토형 장표로 넘긴다.

### 검토/문서 장표의 이미지 배치

- 이미지는 근거 자료이므로 정렬과 크기를 맞춘다.
- 표, 캡처, 사례 이미지는 같은 높이의 프레임 안에 넣고 캡션 기준선을 맞춘다.
- 본문형 장표에서는 장식 이미지를 크게 깔지 않는다. 이미지가 필요하면 우측 30~40% 영역에 배치한다.
- 화면 캡처는 읽을 수 있어야 한다. 읽히지 않는 캡처는 썸네일로 쓰고 핵심 내용은 텍스트로 재작성한다.

### 장식용 보조 이미지

- 장식 이미지는 내용과 관련된 사물, 장면, 질감, UI 일부여야 한다.
- 장식 이미지는 본문보다 약하게 보여야 한다. 투명도, 어두운 오버레이, 부분 크롭을 사용한다.
- 원본처럼 여러 이미지를 겹치는 경우, 겹침은 2~3개까지만 사용하고 주 이미지의 식별성을 해치지 않는다.
- 기울어진 이미지나 폴라로이드식 배치는 레퍼런스/아이디어 보드에서만 사용한다.
- 원형 확대 컷, 작은 썸네일, 하단 스트립은 분석 포인트를 보조할 때 사용한다.

권장 배치 패턴:

| 패턴 | 사용처 | 배치 |
|---|---|---|
| 풀블리드 배경 + 하단 블랙 밴드 | 표지, 섹션 전환 | 배경 100%, 하단 20~30% 어두운 정보 영역 |
| 좌측 텍스트 + 우측 이미지 | 콘셉트 설명, 사례 설명 | 좌측 55~60%, 우측 35~40% |
| 3분할 이미지 보드 | 사례 비교, 레퍼런스 정리 | 이미지 3개 같은 높이, 하단 캡션 정렬 |
| 중앙 큰 이미지 + 주변 콜아웃 | 핵심 화면 분석 | 중앙 60~70%, 콜아웃 2~3개 |
| 하단 결론 바 | 이미지 보드, 검토 요약 | 하단 8~12% 오렌지/블랙 바 |

## 8. 레이아웃 가이드

### 피칭/스토리 장표

- 검은 배경 또는 어두운 이미지 배경을 사용한다.
- 큰 메시지 1개와 보조 설명 1~2줄만 둔다.
- 오렌지 라벨, 짧은 선, 작은 메타 텍스트로 강조한다.
- 이미지가 배경일 경우 텍스트 가독성을 위해 어두운 오버레이를 추가한다.

### 검토/문서 장표

- 흰 배경을 사용한다.
- 표, 타임라인, 비교 프레임, 체크리스트를 중심으로 구성한다.
- 블루를 구조색으로 사용하고, 결론이나 리스크만 오렌지로 강조한다.
- 정보가 많아도 제목 영역은 충분히 비워 첫 읽기 방향을 유지한다.

### 이미지 보드 장표

- 이미지 2~4개를 같은 높이로 정렬한다.
- 각 이미지에는 1~2줄 캡션만 붙인다.
- 분석 포인트는 원형 콜아웃이나 짧은 선으로 연결하되 3개 이하로 제한한다.
- 결론은 하단 오렌지 바 또는 우측 요약 박스로 정리한다.

## 9. 역할별 레이아웃 분류법

레이아웃은 먼저 `무엇을 전달하는가`로 고르고, 그다음 색상과 이미지 톤을 입힌다. 시각 형태가 비슷해도 역할이 다르면 다른 레이아웃으로 분류한다.

### 9.1 구조/진행 역할

덱의 위치와 흐름을 알려주는 장표다.

- 사용 조건: 표지, 목차, 섹션 전환, 다음 파트 예고, 긴 덱의 현재 위치 안내
- 쓰지 말 조건: 본문 근거, 분석 결과, 결론을 담아야 하는 경우
- 권장 골격: 큰 제목 1개, 작은 메타 정보, 섹션 번호, 짧은 보조 문장
- 우리 스타일 적용: 블랙 배경과 오렌지 선/번호를 쓰되, 정보량은 가장 낮게 유지한다.

### 9.2 결론/요약 역할

핵심 판단을 먼저 고정하는 장표다.

- 사용 조건: 한 문장 결론, 경영진용 요약, 챕터의 핵심 메시지, 발표자가 반드시 남기고 싶은 한 줄
- 쓰지 말 조건: 근거가 여러 축으로 나뉘거나 표/차트가 본문이 되어야 하는 경우
- 권장 골격: 단일 임팩트 메시지, 2~4개 요약 근거, 하단 결론 바 중 하나를 선택한다.
- 분기 기준: 결론이 1개면 블랙 임팩트형, 결론이 2~4개면 요약 근거형, 문단형 설명이 필요하면 문서 요약형으로 간다.

### 9.3 데이터/차트 역할

숫자 변화나 비교를 읽게 하는 장표다.

- 사용 조건: 시계열, 카테고리 비교, 실적/전망 구분, 구성비, 다중 지표 추세
- 쓰지 말 조건: 숫자가 핵심이 아니라 상태 판단이나 옵션 선택이 핵심인 경우
- 권장 골격: 제목은 해석을 말하고, 차트는 근거를 보여주며, 우측 또는 하단에 2~3개 해석 포인트를 둔다.
- 분기 기준: 한 숫자가 전부면 큰 숫자형, 여러 KPI는 대시보드형, 목표/실적/상태가 있으면 평가표형, 실제/전망이 갈리면 실적+전망 차트형으로 간다.

### 9.4 매트릭스/판단 역할

대상을 2개 축이나 기준으로 배치해 의사결정을 돕는 장표다.

- 사용 조건: 우선순위, 포트폴리오, 영향도/시급성, 시장성/역량, 리스크/효과 판단
- 쓰지 말 조건: 축이 명확하지 않거나 단순 목록으로 충분한 경우
- 권장 골격: 축 이름을 먼저 명확히 쓰고, 사분면/구간의 의미를 짧게 붙이며, 강조 대상은 1~3개로 제한한다.
- 분기 기준: 축이 연속값이면 산점/버블형, 명확한 2x2면 사분면형, 3단계 밴드면 우선순위 매트릭스형으로 간다.

### 9.5 옵션 비교/선택 역할

선택지를 평가하고 추천안을 드러내는 장표다.

- 사용 조건: 2~4개 옵션 비교, 기준별 점수, Before/After, 장단점, 추천안 선택
- 쓰지 말 조건: 비교 기준이 없거나 모든 선택지를 같은 무게로 설명만 하는 경우
- 권장 골격: 옵션은 열로, 기준은 행으로 두고 추천안은 블루 또는 오렌지로 한 번만 강조한다.
- 분기 기준: 여러 옵션과 기준이면 비교표형, 한 옵션의 장단점이면 Pros/Cons형, 현재/미래 전환이면 Before/After형으로 간다.

### 9.6 조직/관계/분해 역할

사람, 팀, 원인, 하위 구조의 관계를 보여주는 장표다.

- 사용 조건: 조직도, 프로젝트 팀, 기능별 역할, 이슈 트리, 원인 분해
- 쓰지 말 조건: 시간 흐름이나 우선순위 판단이 핵심인 경우
- 권장 골격: 최상위 노드를 먼저 두고, 하위 단위는 같은 크기와 간격으로 정렬한다.
- 분기 기준: 보고 라인이면 조직도형, 리더와 구성원이면 팀 원형, 기능×역할이면 팀 매트릭스형, 문제 원인이면 이슈 트리형으로 간다.

### 9.7 로드맵/프로세스 역할

시간과 실행 순서를 설명하는 장표다.

- 사용 조건: 단계, 웨이브, 주차별 계획, 산출물, 의사결정 일정, 운영 프로세스
- 쓰지 말 조건: 시간 순서가 약하거나 단순 카테고리 설명인 경우
- 권장 골격: 시간축을 먼저 고정하고, 활동/산출물/의사결정 포인트를 분리한다.
- 분기 기준: 3단계는 셰브론형, 4단계 상세는 테이블형, 큰 전개는 웨이브형, 병렬 업무는 간트형, 일반 흐름은 프로세스형으로 간다.

### 9.8 근거/이미지 보드 역할

시각 자료 자체가 근거가 되는 장표다.

- 사용 조건: 사례 비교, 화면 캡처, 현장 이미지, 레퍼런스, 사용자 반응, 문서 캡처
- 쓰지 말 조건: 이미지가 분위기만 만들고 메시지 근거가 되지 않는 경우
- 권장 골격: 2~4개 이미지를 같은 높이로 정렬하고, 각 이미지에 1~2줄 캡션만 붙인다.
- 분기 기준: 한 이미지가 핵심이면 중앙 이미지+콜아웃형, 여러 사례 비교면 이미지 보드형, 캡처가 읽혀야 하면 문서 검토형으로 간다.

### 9.9 상태/운영 점검 역할

현재 상황을 빠르게 판정하게 하는 장표다.

- 사용 조건: KPI 상태, 진행률, 리스크, 이슈, 목표 대비 실적, 운영 대시보드
- 쓰지 말 조건: 원인 분석이나 전략 선택을 깊게 설명해야 하는 경우
- 권장 골격: 카테고리, 지표, 목표, 실제, 상태를 분리하고 신호 색은 보조로만 쓴다.
- 분기 기준: 4~8개 지표는 KPI 대시보드형, 항목별 목표/실적은 평가표형, 리스크 선택은 우선순위 매트릭스형으로 간다.

## 10. 템플릿 선택 운영 규칙

각 레이아웃은 템플릿 카드로 관리한다. 카드에는 최소한 `사용 조건`, `쓰지 말 조건`, `필수 입력`, `권장 개수`, `텍스트 제한`, `검수 기준`을 적는다. 이 구조가 있어야 작업자가 같은 요청을 받아도 같은 레이아웃을 고를 수 있다.

### 10.1 선택 순서

1. 이 장표가 덱의 위치를 알려주는가? 그렇다면 구조/진행 역할을 고른다.
2. 한 문장 결론이 핵심인가? 그렇다면 결론/요약 역할을 고른다.
3. 숫자의 형태가 핵심인가? 한 숫자, KPI 묶음, 시계열, 구성비, 카테고리 비교 중 하나로 나눈다.
4. 축이 2개 이상인가? 연속축, 2x2, 3단계 밴드 중 하나로 나눈다.
5. 선택지를 평가하는가? 옵션 비교, 장단점, Before/After 중 하나로 나눈다.
6. 관계를 보여주는가? 조직, 팀, 기능, 원인 분해 중 하나로 나눈다.
7. 시간이 핵심인가? 단계, 웨이브, 간트, 프로세스 중 하나로 나눈다.
8. 이미지가 증거인가? 단일 근거 이미지, 이미지 보드, 문서 캡처형 중 하나로 나눈다.

### 10.2 유사 레이아웃 구분법

- 큰 숫자형과 KPI 대시보드형: 숫자 1개가 메시지면 큰 숫자형, 여러 지표를 동시에 봐야 하면 대시보드형이다.
- 일반 차트와 평가표형: 추세/비교를 읽으면 차트형, 목표 대비 상태를 판정하면 평가표형이다.
- 버블/산점형과 매트릭스형: 값이 연속 좌표면 산점형, 구간 이름이 먼저면 매트릭스형이다.
- 옵션 비교표와 Pros/Cons형: 여러 선택지면 비교표형, 한 선택지 검토면 Pros/Cons형이다.
- 조직도와 이슈 트리형: 사람의 보고 관계면 조직도형, 문제의 원인 분해면 이슈 트리형이다.
- 단계형과 간트형: 순차 단계만 보이면 단계형, 여러 업무가 병렬로 겹치면 간트형이다.
- 이미지 보드형과 분위기형 배경: 이미지를 근거로 읽어야 하면 이미지 보드형, 분위기만 만들면 사용하지 않는다.

### 10.3 템플릿 카드 예시

```text
레이아웃명: 우선순위 매트릭스
역할: 매트릭스/판단
사용 조건: 실행안을 영향도와 시급성으로 나눠 우선순위를 정할 때
쓰지 말 조건: 축이 불명확하거나 단순 목록으로 충분할 때
필수 입력: 항목명, 영향도 구간, 시급성 구간, 상태 또는 강조 여부
권장 개수: 5~12개 항목
텍스트 제한: 항목명 12자 안팎, 축 라벨 1~2단어
검수 기준: 축 의미가 제목 없이도 보이는가, 강조 항목이 3개 이하인가
```

## 11. 제작 체크리스트

- 이 장표는 피칭형인가, 검토형인가, 이미지 보드형인가?
- 이 장표의 역할이 구조/결론/데이터/판단/비교/관계/로드맵/근거/상태 중 무엇인가?
- 비슷한 레이아웃 중 왜 이것을 골랐는지 `쓰지 말 조건`으로 설명할 수 있는가?
- 필수 입력이 모두 있는가? 숫자, 축, 기준, 단계, 이미지 근거가 부족한데 레이아웃만 먼저 고르지 않았는가?
- 이미지가 장표 내용과 직접 관련되어 있는가?
- 블러가 필요한 정보 보호 목적에만 쓰였는가?
- 아이콘이 문장 이해를 돕는 역할을 하는가?
- 여백이 부족해 장표가 문서 캡처처럼 답답해지지 않았는가?
- 장식 이미지가 내용과 관련되어 있고 본문보다 약하게 배치되어 있는가?
- 이미지의 크기, 기준선, 캡션 위치가 같은 계열 장표끼리 맞는가?
- 원본처럼 상단 탭, 우측 메타, 하단 결론 영역의 위치감이 유지되는가?
- 제목과 본문의 줄바꿈이 의미 단위로 정리되어 있는가?
- 한글 어절이 중간에서 끊기지 않았는가?
- 난수/익명화 텍스트가 실제 제작 기준처럼 남아 있지 않은가?
- 오렌지 강조가 너무 많아 핵심이 흐려지지 않는가?
- 표/일정/문서형 장표에서 블루 구조색이 일관되게 쓰였는가?
- 작은 글씨가 발표 장표에 과도하게 남아 있지 않은가?
- 같은 덱 안에서 폰트, 상단 메타, 라벨 스타일이 유지되는가?
